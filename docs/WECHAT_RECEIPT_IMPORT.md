# 微信经营收款小票导入

适用入口：微信收款助手 → 经营收款 → 下单助手 → 小票单 → 右上角菜单 → 导出小票单。不是微信小店订单接口，也不自动读取微信账号。

## 使用

1. 导出所需日期的原始 `.xlsx`，保留顶部店名、笔数、金额汇总及业务列。
2. 登录利润本，在「销售记录」点击「导入微信小票」，选择文件。
3. 预览小票。名称唯一相同的已有商品会自动对应；其余选择已有商品或新建，并填写实际每件成本。真实成本为零需明确填 `0`。
4. 核对收入、额外收入、商品成本和估算毛利润，确认均已收款、未退款后，点击「确认导入」。未确认或成本未补齐时不能保存。
5. 保存后查看新增、跳过及未完成笔数。中途失败会保留成功记录；刷新后可重新选择同一文件继续，不会自动重试发送未知结果的写入。
6. 微信小票默认勾选「只记销售和利润，不改变库存」，新增小票只计算收入、成本和利润，不更改任何库存；编辑、作废这些小票也不会改变库存。需要按原规则扣库存时，可主动取消勾选。保存失败后也可直接切换方式，保留原文件和已填成本，重新核对后再导入；已有小票始终跳过，不会因切换方式重写。

## 数据规则

- 每份最多 2 MB、500 笔、100 种商品；解压后总量不超过 16 MB，单 XML 不超过 8 MB，最多 100 个 ZIP 条目。工作表最多 10000 行、64 列。超出时缩小导出日期范围。
- 微信原导出可能没有单元格坐标，读取器仅在内存补齐，不修改原文件。售价和实收按整数分核算；商品金额列视为单价，乘以数量后与实收比较，正差额记额外收入。单位成本保留最多三位小数（整数厘）；每条明细先乘数量再四舍五入到分，然后汇总，经营概览和商品排行使用同一口径。
- 退款标记、非零/无法确认的优惠、实收小于商品合计、未知来源、同文件无法区分的重复小票均留待核对，不自动记账。表头、日期、金额、数量或顶部汇总不符时拒绝整份，防止截断错账。
- 原文件无支付交易单号。按来源店名、完整收款时间、金额和排序后的商品明细生成稳定指纹；再按利润本店铺生成稳定销售 ID。重叠日期导出仍能检查已有小票，已作废的小票也不会复活。完全相同的不同交易需要人工核对后手动记账；改了来源业务内容也可能改变识别结果。
- 仅创建新销售，绝不调用历史销售编辑路径。销售保留原小票单价、数量、日期、额外收入、核对后的成本快照和来源时间/指纹备注。匹配已有商品时，不修改该商品当前资料；新商品分类为「微信导入」。
- 首次创建和中断重试均使用稳定商品 ID、销售 ID 和请求 ID；数据库的现有防重规则处理同时导入。不是全批事务，创建商品后销售失败时该商品可能保留，可在商品管理中查看。
- 文件仅在浏览器读取，不上传 Excel。客户昵称、姓名、电话、地址和客户/商家备注不进入解析结果或云端账本，也不用于指纹。允许删除这些隐私列，业务列和顶部汇总仍需保留。

## 验证边界

离线解析、批次写入模拟、实际导出文件读取和本地界面检查均不写入真实账本。真实进货成本由店主填写并最终确认。现有账号验证、数据库按账号隔离和 API 代理接口限制不变；无需新数据库表或云服务。
