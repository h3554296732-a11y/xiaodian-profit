## 方案范围

- 前端：OSS 中国香港（`cn-hongkong`）、标准存储、本地冗余 LRS、按量付费，托管现有 Next.js 静态导出的 `out/`。
- 正式主地址为 `https://lirunben.cn`。DNS 与匹配证书已生效，7 个页面正常 TLS/内容哈希验证及真实 404 通过，浏览器登录页正常渲染；Supabase Site URL 和精确 `/account/` 回调已保存并重新加载核实。用户实际登录、完整邮件回跳和朋友原网络仍待验证。本方案未增加 CDN、ESA 或 ECS。
- 后端：沿用现有 Supabase 数据库、认证、短信 Hook 和 RLS，不搬迁商户数据。
- 原 Sites 部署保留。独立托管不等于已解决所有网络问题，朋友原网络到 Supabase 的连通性仍未验证。

## 域名、HTTPS 与路由

- 阿里云现行 OSS 文档明确：香港、新加坡等非中国内地 Bucket 绑定自定义域名无需 ICP 备案；内地 Bucket 则需要。域名实名认证是另一项要求，须确认已通过的模板已关联到 `lirunben.cn`。[域名接入要求](https://help.aliyun.com/zh/oss/user-guide/access-buckets-via-custom-domain-names)、[实名认证](https://help.aliyun.com/zh/dws/security-and-compliance/domain-name-real-name-authentication)
- 默认 OSS 域名可能强制下载 HTML；自定义域名支持在线展示。上传时核对 HTML、CSS、JS 的 `Content-Type`，不设置 `Content-Disposition: attachment`。[文件预览规则](https://help.aliyun.com/zh/oss/download-file-faq/)
- 自定义域名直接使用 OSS 证书托管即可启用 HTTPS，不要求增加 CDN。证书必须覆盖 `lirunben.cn`，并通过浏览器正常验证。[HTTPS 配置](https://help.aliyun.com/zh/oss/user-guide/access-oss-by-https-protocol)
- 历史部署使用 Let's Encrypt，通过DNS-01验证签发免费生产证书，并导入阿里云供OSS托管；未购买付费证书或额外服务。证书只覆盖所需域名，线上指纹需与部署时记录一致。证书与私钥保存在仓库外的受保护目录，到期前需重新签发并部署；历史方案未配置自动续期。
- 当前项目为 `output: "export"`、`trailingSlash: true`。OSS 默认首页设为 `index.html`，**开通子目录首页**，文件 404 规则使用 Redirect，使 `/account` 可转到 `/account/` 并返回对应 `account/index.html`。不存在的路由返回实际 404，不把所有路径回退到根首页。[静态网站托管](https://help.aliyun.com/zh/oss/user-guide/hosting-static-websites)
- 本方案以明确的 HTTPS 地址对外分享；直接 OSS 不提供 CDN 式 HTTP→HTTPS 自动跳转，不将这项能力作为已实现功能。

## 实施顺序与当前进度

1. 香港标准 LRS 按量部署范围和 OSS 开通订单已获用户批准，现有 Bucket 已由用户创建。后续证书选择按实际页面核对；记录现有 DNS 与 Supabase URL 配置以便回滚，不记录密钥。
2. 为当前确定版本重新构建和检查独立静态包。只发布 `out/` 中网站需要的 HTML、CSS、JS、图片等公开产物，**不上传**源码包、`.env*`、服务端密钥、CSV 凭据、QA 账号资料、邮件、测试账单、日志或 `artifacts/`。前端公开资源不保存商户业务数据；商户数据继续由 Supabase 认证和 RLS 保护。
3. 准备 OSS 静态文件、目录首页、元数据和 HTTPS。公开范围仅限上述静态产物，上传管理权限不向匿名用户开放；不关闭现有网站、认证或数据库的安全防护。
4. 在切换前先向 Supabase 的允许重定向列表**补充精确的新域名回调地址**，保留原 Sites 地址，不使用宽泛通配符。此时先不替换 Site URL。核对应用构建配置与回调路径，必要时重新构建。
5. 仅为 `lirunben.cn` 添加方案所需的域名验证及根主机记录 CNAME，使用 OSS 实际提供的目标值，不猜测记录值。**保留 Resend 发信 DNS**，包括 `resend._domainkey.auth`、`rsend.auth`、`send.auth` 以及其他现有邮件记录；不改 `auth` 发信域名或已有邮件配置。2026-10-18 绑定前公开 DNS 查询未返回根域名 A、AAAA 或 CNAME 回答，只返回 SOA；不将此结果视为 DNS 控制台全部记录的备份。
6. DNS 与证书生效后，先核对新地址及所有业务页面的直接访问、刷新、静态资源与 404。通过后才把 Supabase Site URL 和必要的邮件链接配置切换到新正式地址，继续保留原地址的精确允许项。
7. 完成下方实际验收后再把新地址作为主要分享入口。未通过时保留原部署和验收记录，按具体失败层继续排查。

## 验收与回滚

朋友需使用**原手机、原 Safari、原移动网络**验收，再补充普通 Wi-Fi 对照；不能用开发电脑成功代替朋友成功。

- 首页与 `/account/`、`/products/`、`/sales/`、`/expenses/` 直接访问和刷新正常，HTTPS 无证书错误、HTML 不触发下载。
- 浏览器能连接现有 Supabase；邮箱注册、实际收信、确认链接、找回密码，以及手机收码和登录均完成一次实际闭环。若页面正常但后端不可达，仍判定未通过，不宣称迁移已修复注册。
- 未登录用户不能记账；两个独立测试账号各自建立店铺和样例数据，正向 CRUD 正常，交叉读取、修改、删除及 RPC 操作被隔离。刷新和重新登录后结果仍一致。
- 记录测试时间、网络、版本、通过/失败及脱敏错误信息，不把密码、OTP、令牌或真实经营数据写进文档。

保留原 Sites 部署、原静态发布包、DNS 和认证 URL 的原值。新站失败时按记录恢复根主机 `@` 的 DNS 及 Site URL/邮件链接配置，保留恢复所需的精确重定向地址；不删除 Supabase 用户或商户数据，不改 Resend DNS。回滚至原站不代表朋友原网络一定恢复，因为原 `chatgpt.site` 安全阻断仍可能存在。回滚后重新验证实际可达的入口与登录，确认后再向用户说明状态。

香港节点访问仍经过跨境链路，阿里云文档提示可能增加延迟；本方案不保证中国内地所有运营商可达，也不替代独立的后端网络和账户隔离验收。
